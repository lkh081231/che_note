# CIE 真题库：从零搭一个新科目

**唯一的参考实现是 Chemistry 9701 Paper 2 (2024–2026)**：77 题 / 960 分 / 16 卷，
在 `c:\che_note\passyear\`。那一轮的完整工作流文档是 `passyear/CLAUDE.md`，
踩坑记录在 `passyear/BUDGET.md`。**动手前值得去翻一眼实物**，比读描述快。

本 skill 讲的是**哪些东西可以直接搬、哪些必须按科目重做**。

---

## 先决条件：syllabus 得先在库里，而且只读

整套方法的地基是「**syllabus 全文转写成 Markdown，当作分类与判题的唯一依据**」。
化学那套是 37 章 / 90 subsection / 538 outcomes，逐条对着 PDF 核过。

没有它就没法做章节分类，也没法在争议时裁决——本次至少三次关键判断
（sulfur 归哪章、mass spectrum 归哪章、结构与性质归哪章）都是靠 `grep` outcome 原文定的。

**转写完就把它设成只读**：装一个 PreToolUse hook 拦 `Edit`/`Write`/`NotebookEdit`/`MultiEdit`
指向它的写入，以及 `Bash`/`PowerShell` 里「文件名 + 写操作同现」的命令；读一律放行。
subagent 走同一条 hook 管线，一并被拦。参考 `c:\che_note\.claude\hooks\protect_reference.py`。

> ⚠️ 这个 hook 会误伤你自己的日志：往 `BUDGET.md` 写一段提到那个文件名的文字时会被拦。
> 绕法是先用 Write 工具写暂存文件，再 `cat 暂存 >> BUDGET.md`——hook 查的是命令串不是文件内容。

---

## 第一步永远是侦查，不是下载

花半小时对 2–3 份目标 PDF 做技术摸底。**结论决定后面所有事**，尤其这一条：

**有没有干净的文字层？**

- **有** → 走确定性抽取。机械正确性全部用 Python 做完，模型只干版式和判断。
  这是省额度和保质量的关键。
- **没有（扫描件）** → 本工作流不适用。得先做 OCR 质量摸底，那是另一套流程，
  成本高一个数量级。CIE 2015 年前后的卷、以及第三方的 topical 合集，多半是扫描件。

再看：`get_images()` 是不是 0（图全是矢量 → 裁 PNG 可任意 dpi）、每份多少分多少题多少页、
mark scheme 是什么结构。

## 七个阶段

详细机制见 **`references/playbook.md`**。这里只讲每阶段的要害。

| 阶段 | 要害 |
|---|---|
| **0 侦查** | 有无文字层决定一切；换 Paper 要重测，别假设 Paper 1 和 Paper 2 一样 |
| **1 下载去重** | PapaCambridge 直链可拼；**不存在的组合返回 200 + 占位 PDF，判空看文件大小** |
| **2 抽取** | 确定性 Python，**绝不让模型猜**；上下标/角标在 span 层可复原 |
| **3 裁图** | caption 锚定带状裁剪，不要走 `get_drawings()` 聚类 |
| **4 分类** | **必须先于分工**；按 outcome 原文定章，不按标题望文生义 |
| **5 派活** | **一个 subagent 独占一个 chapter 文件夹**（写者唯一 → 无写冲突） |
| **6 跨章镜像** | 正本一份放主章，够分量的其它章拿整题镜像 |
| **7 验收** | 全部做成 grep 能跑的机械检查 + 少量人眼抽查 |

## 六条跨科目都成立的经验

### 1. 机械正确性前置，模型只做判断

抽取器把上下标、噪声、切题全部处理干净之后再派活。执行体拿到的是干净文本，
只需要看图核对版式、对账数字、做归章判断。**这既是质量保证，也是省额度的关键。**

反过来说：凡是能写成 grep / 脚本的检查，就不要指望人或模型逐字通读。

### 2. 视觉核对不可省，而且是主 session 也要看

「凡带公式 / 方程 / 结构式 / 图表的小问，裁题后必须对渲染页看一遍」——
这条规矩在每一章都抓到了真错误。抽取器再好也会漏（分数系数 `1½` 丢成 `1`、
算术符号 `×` `>` 被当噪声滤掉、方程两边被颠倒）。

同时**主 session 不能全信执行体的结论**。本次有两次执行体信誓旦旦报「官方 PDF 有缺陷」，
一次是它自己数错了骨架式的碳数（主 session 看图推翻），一次是真的（官方 MS 缺一整题，
主 session 重下核实后确认）。**必须亲自看图才能分辨**。

### 3. 分类要以 outcome 原文为准，不要按章节标题望文生义

栽过两次（都在化学，但机制是通用的）：

- 章节叫「Chemical bonding」，但「结构 → 物理性质」这条 outcome 其实写在
  「States of matter」那一章 → 整章热度虚高了 3 倍
- 章节叫「Nitrogen and **sulfur**」，5 条 outcome 却全是 nitrogen

**任何科目的 syllabus 都有这种「标题与实际 outcome 不对齐」的地方。**
拿不准就 `grep -n` 去找那条 outcome 的原文。

### 4. 统计口径要按大类，不按 chapter

CIE 的 chapter 切得很碎，单章分值上下浮动大，当复习优先级看没意义。
按 syllabus 自己的顶层编排分组（化学是：物理化学逐章 + 无机 / 有机 / 分析各一块；
物理大概是 力学 / 热学 / 波 / 电磁 / 近代；经济是 微观 / 宏观 / 国际）。

多章小问在**同一大类内只记一次，跨大类才各记一次**——不然合计会虚高很多。

### 5. 一个 subagent 独占一个 chapter 文件夹

写者唯一 → 无写冲突。按卷分工会让多个 agent 同时写同一份卷。
而且一个执行体只在一个主题里打转，学科上下文建立一次反复用，比按卷跳 5 个不相干主题
更省额度也更一致。

每个 agent **只做 1 个 chapter，做完即结束**。先开 1 个试点测单章成本，
再据此排批；并发起手 2，稳了加到 4。

### 6. 额度是主刹车，时间是次刹车

**绝不主动跑进 extra usage**，剩余 ≤ 15% 一律停。
**别建成本模型**——本次估 12% 实际 34%，直接作废。用 VS Code 侧栏
`ACCOUNT & USAGE` 面板的前后读数当唯一依据（那个百分比是**已用**不是剩余）。

**5 小时窗口从「本窗口第一次调用」起算、刷新点会漂**，不是固定钟点。
挂定时任务一律「**一次性 cron + 刷新时刻后留 10 min 冗余**」，
且 cron prompt 第一条指令必须是「先复核面板确认窗口真的换了，没换就重挂」。

实测量级（化学，供换算）：提取约 6.7–11 额度点/章、28–36k subagent token/题。
主 session 的 context 长度显著影响单章成本——compact 之后同样的活从 11 点掉到 6.7 点。

## 按科目要改什么

**`references/subject-variations.md`** 列了各科的差异。最要紧的一条：

**Mark scheme 的结构随科目变，产物格式必须跟着变。**
化学 / 物理 / 生物是 point-based（`Answer / Marks / Guidance` 四栏表，逐点给分），
可以逐点抄。经济 / 商务 / 心理 / 历史的论述题是 **level descriptors**（Level 1–4 的整体
描述 + indicative content），逐点抄没有意义，得改成「层级 + 该层要害 + 典型 indicative content」。

数学的 mark scheme 有 M/A/B 分类型（Method / Accuracy / independent），
这个信息比化学的 Guidance 重要得多，不能精简掉。
