# 跨章镜像、小问标注、四个脚本、验收清单

## 为什么要镜像

一道 CIE 大题经常横跨好几章（实测 77 题里 **43 题是跨章的**，一道 19 分的题能压到 9 个章）。
按 chapter 刷题的人不希望「这道题主章是 ch7 所以 ch15 文件夹里看不到它」。

口径：**正本只有一份放主章，够分量的其它章拿整题镜像。**

## 小问级标签

正本里给**带 `[n]` 分值的**小问标上它实际考的章：

```markdown
### (b)(iii) [3] · ch9
### (c) [4] · ch16 ch17        ← 真两边都占分才双标
### (a) The chlorides of Period 3 …   ← 没有 [n] 的铺垫行，不标
```

格式写死成「一个空格 + `·` + 一个空格 + `chN`」，为的是能 grep。

**只标跨章的题。** 单章题无歧义，标了纯属浪费额度。

## 镜像门槛：≥2 分 **且** ≥15% 题分

只卡绝对分会让镜像爆炸。实测有道 17 分的题散进 8 个章、每章才 1–2 分，
整题镜像进去全是噪音；只卡 ≥2 分的话 43 题会外推出 **108 个镜像**，加上占比条件降到 88 个。

够不上门槛但确实考到的，**不做整题镜像，改成在该章 README 里列一条「零星考点」指路**——
这样 ch6 那 2 分的 oxidation number 仍然找得到，但 ch6 文件夹不会被一道 17 分的
periodicity 大题占据。

## 四个脚本，顺序不能错

| 脚本 | 干什么 |
|---|---|
| `mirror.py` | 按标签算镜像目标，重写正本 + 生成镜像 + 各章 README；顺手删过期镜像与孤儿图 |
| `verify.py` | 机械验收（见下） |
| `audit.py` | 挑出**主章被标空 / 主章不是最大块 / 有小问漏标**的题 |
| `heat.py` | 按标签重算分值分布，喂 `classification.md` 的热度表 |

### ⚠️ `mirror.py` 会重写正本文件

**跑标注 subagent 期间绝对不要执行它**，会和执行体的 Edit 撞车。必须等所有 agent 报完工。

实测撞过一次：脚本按新门槛正确删掉了一个镜像块，执行体误以为「文件被截断」，
又手工重建了一遍。脚本 docstring 顶部已加警告。

`mirror.py --check` 是 dry-run，只报要改什么、不落盘。**删文件前先跑它看清单。**

### `audit.py` 为什么必须存在

`mirror.py` 只认 `chapters.py` 里定死的主章、不会自己改，所以「**主章在自己题里占 0 分**」
这种事它发现不了，`verify.py` 也发现不了（镜像块本来就不计分，960 照样对得上）。

实测抓到两类：

- **ch21 整章被标空**（执行体漏了「能力型」outcome，见 `dispatch.md`）→ 派回去返工
- **我自己 Phase A 分类判错**：`s25_22 Q1` 主章 ch3 却一分 ch3 都没有，
  因为「lattice 结构 → 物理性质」在 4.2 不在 ch3 → 这类是判断题，列出来给人拍板，不自动改

### `mirror.py` 修过的一个真 bug：过期镜像不会被删

脚本报「镜像块 88 个」，但 `grep` 数出文件里有 **105 个**。差的 17 个是**门槛变化后遗留的
旧镜像文件**——脚本只按 `plan` 重写文件，从不删除掉出 `plan` 的文件。

`verify.py` 抓不到（镜像不计分）。已在 `build()` 末尾补两段清理：
删 `(ch, key) not in plan` 的 md（正本一定在 plan 里，所以删掉的只可能是过期镜像）、
删该章 `img/` 下没有任何 md 引用的图。

## 统计口径：按大类，不按 chapter

**CIE 的 chapter 切得很碎**（ch10 Group 2 只有几条 outcome，ch20 Polymerisation 更少），
单章分值上下浮动大，当复习优先级看没意义。分组按 syllabus 自己的编排：

```
1–2 Atomic structure & stoichiometry · 3 · 4 · 5 · 6 · 7 · 8
9–12 Inorganic · 13–21 Organic · 22 Analysis
```

一个小问同时压两章时：**同一大类内只记一次**（`ch16 ch17` 都是有机），
**跨大类才各记一次**（`ch15 ch22` = 有机 + 分析）。
这样合计 969 只比 960 多 9 分；按 chapter 算是 1023，虚高 63 分全来自有机内部的同类双标。

实测结果（9701 P2 2024–2026）：有机 34% + 无机 24% = **58% 是绝对重心**，
物理化学各章分散、单章都不超过 8%。

**两个口径能差得非常远**，这正是新口径的价值：

| 章 | 主章口径 | 小问口径 |
|---|---:|---:|
| ch3 Chemical bonding | 144 分（第 1） | 49 分（第 8） |
| ch13 Organic intro | 27 | 64 |
| ch22 Analytical techniques | 8 | 40 |
| ch6 / ch19 / ch20 | 0 / 0 / 0 | 12 / 8 / 5 |

「主管」这个口径决定的只是**正本文件放在哪个文件夹**，不是复习权重。
ch13 / ch22 那种「遍地都是但从不独立成题」的章，主章口径完全看不见。

## 验收清单（`verify.py` 跑的都是 grep 能验的）

1. `grep -rE 'SF6|3s2|mol–1|H2SO4|SO42' extracted/` **零命中**（命中即上下标未还原）
2. `grep -rn 'ℓ|\$\$|(_img/|&lt;' extracted/*/*.md` **零命中**
   —— script ℓ、块公式、误引临时渲染目录、HTML 实体未转义
3. `grep -rln '本卷与 9701/23 同卷'` **只能命中 `9701_w24_21.md` 与 `9701_w25_21.md`**
   —— variant 2 在任何会期都是独立卷（实测有执行体凭空补过这条）
4. 中文化学名零命中：`grep -rnoE '环[丙丁戊己庚辛]烷|[一-龥]{2,}酸[一-龥]?[乙甲]酯'`
5. 每个 `![…](img/…)` 都指向存在文件
6. 每道大题恰好落在一个 chapter 文件夹；**同一卷跨各章的 `[n]` 求和 = 60**
7. 镜像块不计分（否则总分会翻倍）
8. `git status` 里 syllabus 文件恒为 clean

人眼补两条：VS Code preview 看 `$…$` 与 ChemFig 渲染；随机抽 10 个小问对 MS 核数值。
